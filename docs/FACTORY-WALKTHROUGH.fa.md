# راهنمای مسیر یکپارچهٔ Factory — نسخهٔ آزمایشی

این قابلیت در **همین** مخزن \`CSEF-Execution-Agent\` ساخته شده است و از اجزای فعلی استفاده می‌کند: \`ProjectBook\`، دو \`DirectAPI\`، پل Spec Kit، اعتبارسنج \`task_graph\` و \`Gate\`. هستهٔ امنیتی بازنویسی نشده است.

> **محدودیت مهم:** مسیر یکپارچه برای **یک برش کوچک Python CLI** پیاده شده است. ساخت خودکار همهٔ انواع وب‌اپ و برنامه‌های چندزبانه یا اجرای امن کد غیرقابل‌اعتماد روی Windows/VPS هنوز اثبات نشده است. محیط فعلی Docker reviewed-only فقط \`REVIEW\` می‌دهد و ZIP تأییدشده نمی‌سازد. آزمون یکپارچهٔ CI از کد واقعی Python استفاده می‌کند، اما backend ایزولهٔ آن صرفاً test double است.

## ۱. ثبت شرح‌حال و پاسخ‌های قطعی مالک

\`\`\`bash
python -m csef_gate.factory start --root ./factory-book --brief "یک CLI پایتونی برای مدیریت موجودی بساز" --answers ./owner-answers.json
\`\`\`

فایل \`owner-answers.json\` باید چهار پاسخ واقعی مالک را داشته باشد: \`users\`، \`workflow\`، \`success\`، \`constraints\`. اگر هنوز پاسخ ندارید، گزینه \`--answers\` را حذف کنید؛ امکان تولید **پیشنهاد** وجود دارد ولی اجرای نهایی تا تعیین مجهول‌های لازم مسدود می‌ماند.

\`start\` متن واقعی شرح‌حال را عیناً به \`REQ-001\` متصل می‌کند؛ جزئیات ناشناخته را به‌عنوان حقیقت کاربر نمی‌سازد.

## ۲. تولید طرح و گراف وظایف

با کلید خصوصی OpenAI یا Anthropic در متغیر محیطی مناسب و مدل صریح:

\`\`\`bash
python -m csef_gate.factory plan --root ./factory-book --provider openai --model YOUR_ENABLED_MODEL
\`\`\`

خروجی مسیر \`plan_path\` را می‌دهد. در کنار آن \`spec-kit/spec.md\`، \`spec-kit/plan.md\`، \`spec-kit/tasks.md\` و \`plan.json\` تولید می‌شوند. این فایل‌ها **صرفاً پیشنهادند**. قراردادها بررسی می‌کنند که تمام حقایق مالک پوشش داده شده‌اند، وابستگی‌ها بدون چرخه هستند، مالکیت فایل‌ها مشترک نیست، معیارها و شناسه‌های آزمون وجود دارند، و نسخهٔ مالک معتبر است.

این مرحله هزینهٔ API دارد؛ فراخوانی بدون انتخاب صریح ارائه‌دهنده/مدل انجام نمی‌شود. هزینهٔ واقعی دلاری بدون تعرفهٔ معتبر، نامعلوم گزارش می‌شود.

## ۳. تثبیت معیار مستقل

کاربر طرح تولیدشده را بررسی می‌کند و در فایل \`approved-oracle.json\` مجموعهٔ آزمون **مستقل و قبل از شروع کدنویسی** را تعیین و تأیید می‌کند. ساختار آن مانند \`examples/expense_cli/acceptance.json\` است، با این تفاوت که شناسه‌های \`cases\` باید دقیقاً با شناسه‌های \`test_ids\` در گراف وظایف برابر باشد. فایل‌های \`source_files\` / \`editable_files\` نیز دقیقاً با مالکیت فایل‌های تسک‌های برش تطبیق دارند.

**محدودیت MVP:** تعداد وظایفِ یک اجرای کامل بیشتر از \`max_attempts\` در Gate (حداکثر ۵) نباشد؛ برنامهٔ بزرگ‌تر باید به برش‌های مستقل با آزمون پذیرش مخصوص تقسیم شود. این کار بدون بازنویسی Gate امکان‌پذیر است.

برای منبعهای تازه و دورریختنی، از فرمان زیر برای ایجاد اسکلت **بدون دست‌زدن به پوشهٔ موجود** استفاده کنید:

\`\`\`bash
python -m csef_gate.factory bootstrap --project ./candidate --oracle ./approved-oracle.json
\`\`\`

## ۴. اجرا و ارزیابی مستقل

فقط پس از بازبینی طرح و oracle، و به‌صورت آگاهانه:

\`\`\`bash
python -m csef_gate.factory build \
  --root ./factory-book \
  --plan ./factory-book/factory-plans/PLAN_ID/plan.json \
  --project ./candidate --oracle ./approved-oracle.json \
  --provider openai --model YOUR_ENABLED_MODEL \
  --executor docker-reviewed --measure-only \
  --docker-image python:3.11-slim@sha256:REAL_VERIFIED_64_HEX_DIGEST \
  --approve-plan --output ./delivery.zip
\`\`\`

مقدارهای \`PLAN_ID\` و digest را از خروجی‌های واقعی خود جایگزین کنید. اگر Docker و ایمیج معتبر ندارید، اجرا متوقف می‌شود؛ **هیچ fallback به اجرای آزاد روی میزبان وجود ندارد**.

هر تسک فقط فایل‌های تحت مالکیت خودش را به عامل می‌دهد و Gate اجازهٔ نوشتن در فایل/معیار محافظت‌شده را نمی‌دهد. Gate بعد از کامل‌شدن برش، آزمون‌های frozen oracle را روی snapshot اجرا می‌کند. در صورت شکست، اصلاح فقط در محدودهٔ تسک صاحب آزمون مجاز است. هر درخواست به API یک تلاش مصرف می‌کند؛ اجرای نامعلوم برای جلوگیری از اثر تکراری بدون بازبینی صریح دوباره انجام نمی‌شود.

**در \`docker-reviewed --measure-only\`، حتی اگر همهٔ آزمون‌های رفتاری موفق شوند، وضعیت \`REVIEW\` می‌ماند، checkpoint ایجاد نمی‌شود و \`delivery.zip\` ساخته نمی‌شود.**

## ۵. تحویل قابل استفاده پس از PASS

فقط وقتی \`ExecutionProvider\` مستقل با مرز ایزولاسیون واقعی بررسی‌شده در دسترس باشد و Gate واقعاً \`PASS\` دهد، \`checkpoint\` ایجاد می‌شود. سپس بستهٔ ZIP شامل منبعهای تست‌شده، راهنمای اجرا و \`manifest.json\` با SHA-256 و شناسه‌های آزمون تحویل می‌شود. موفقیت Gate، مجوز استقرار عمومی یا ادعای ممیزی کامل امنیت نیست.

## شواهد CI و کارهای باقی‌مانده

آزمون‌های موجود به‌علاوهٔ \`tests/integration/test_factory_pipeline.py\` باید سبز باشند. این تست یک نمونهٔ واقعی Python CLI را از طرح تا تولید دو ماژول، اجرای subprocess و ساخت بستهٔ نهایی **با test-double محیط اجرا** می‌سنجد، و همین‌طور لغو تحویل در \`REVIEW\`، خروج از محدودهٔ فایل، تغییر هدف، شرط تصویب مالک، ناقص‌بودن oracle و وقفهٔ ناشناخته را پوشش می‌دهد.

باقی‌مانده: guest مستقل آزموده‌شده، اجرای واقعی با اعتبارنامهٔ کاربر و بررسی کیفیت مدل، گردش‌کار پروژه‌های وب/چندزبانه، برنامه‌ریزی بیش از یک slice و بازیابی عمومی از تمام نقاط وقفه. تا اثبات آن‌ها، ادعای «کارخانهٔ خودمختار کامل» درست نیست.
