# اعتبارسنجی اولیهٔ گراف وظایف پروژهٔ کاربر

این ابزار فقط **ساختار پیشنهاد تقسیم کار** را می‌سنجد؛ پروژه را نمی‌سازد، مدل فراخوانی نمی‌کند و مجوز پذیرش یا انتشار نمی‌دهد.

## پیش‌نیاز

یک ProjectBook معتبر CSEF با \`ProjectBook.create\` یا CLI پروژهٔ موجود داشته باشید. پیشنهاد باید دقیقاً به \`version\` و \`sha256\` همان ProjectBook اشاره کند. شناسهٔ تمام واقعیت‌های پذیرفته‌شدهٔ مالک باید دست‌کم در یک تسک ذکر شود. در صورت اصلاح هدف، گراف قدیمی رد می‌شود.

## نمونهٔ قرارداد JSON

\`\`\`json
{
  "schema_version": 1,
  "project_version": 1,
  "project_sha256": "64-character-current-owner-sha256",
  "tasks": [
    {
      "id": "TASK-001",
      "title": "ساخت ذخیره‌سازی",
      "fact_ids": ["REQ-101"],
      "depends_on": [],
      "files": ["app/db.py"],
      "deliverable": "داده‌های برنامه ذخیره و بازیابی می‌شوند",
      "acceptance": "ثبت و بازیابی یک رکورد بدون خطا",
      "test_ids": ["TEST-001"]
    }
  ]
}
\`\`\`

\`project_sha256\` را از \`ProjectBook.current()\` بگیرید؛ مقدار نمونهٔ بالا معتبر نیست. هر شناسهٔ واقعیت باید در ProjectBook موجود باشد. برای هر فایل فقط یک مالک تسک تعیین کنید. هیچ فایل یا آزمون توسط این ابزار ساخته یا اجرا نمی‌شود.

## اجرای آفلاین

\`\`\`powershell
python -m csef_gate.engineering.task_graph --book PATH_TO_PROJECTBOOK --graph PATH_TO_TASK_GRAPH_JSON
python -m pytest -q tests/engineering/test_task_graph.py
\`\`\`

در صورت اعتبار ساختاری، خروجی \`status: proposed\`، فهرست تسک‌های آماده و ترتیب توپولوژیک می‌دهد؛ \`release_approved\` همیشه \`false\` است. \`ready_tasks\` تنها پیش‌نمایش وابستگی است؛ فهرست completed ورودی، مدرک پذیرش نیست. پیش از اجرای هر تسک باید کنترل مستقل، محدودهٔ فایل، محیط امن و Gate مراحل بعد برقرار شوند.

**محدودیت:** حضور شناسهٔ نیاز در تسک، انطباق معنایی با آن نیاز را ثابت نمی‌کند. این validator همچنین هنوز تولید خودکار گراف از شرح‌حال یا ادغام خودکار آن با اسناد Spec Kit را انجام نمی‌دهد.
